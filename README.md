# Summer 工作台 Lite

一个纯本地的行动记录器：随手记、自动整理、每日复盘、手机与电脑同步，也可以按需连接 Cola 或其他 AI。

## 这个仓库就是公开入口

这是 Summer 工作台 Lite 的唯一公开 GitHub 仓库。粉丝直接在 GitHub 搜索“Summer 工作台 Lite”或“summer-workbench”，进入本仓库即可使用和查看源码，不需要向作者索取安装包，也不需要登录 Cloudflare。

- 最新源码以 `main` 分支为准。
- Release 只是可选的快捷下载入口，不能作为另一套产品维护。
- 仓库里的 `Summer工作台-Lite.zip` 是给不想配置开发环境的普通用户使用的运行包。

## 粉丝直接使用

正式发布时，普通用户优先从 GitHub 的 Releases 下载对应系统的安装包：

- macOS：`Summer工作台-版本-mac-x64.dmg`
- Windows：`Summer工作台-版本-win-x64.exe`

安装一次后，直接点击桌面上的“Summer工作台”图标即可。应用会自己启动本地服务、保留记录和头像，并在后台检查更新。粉丝不需要安装 Python、Node.js，也不需要寻找或运行 `start.command`。

仓库根目录的 `Summer工作台-Lite.zip` 仍然保留，作为没有安装包时的兼容运行包和开发备用入口，不再作为普通用户的首选方式。

在仓库文件列表点击 `Summer工作台-Lite.zip`，再点击下载按钮。解压后：

- macOS：双击 `start.command`。如果系统提示无法验证，右键它，选择“打开”，再选择“打开”。
- Windows：双击 `start.bat`。

浏览器会自动打开工作台。每个人第一次填写自己的昵称和头像，记录保存在自己的设备上，不会带入作者的个人数据。

如果要查看或修改源码，点击仓库上方的 `Code → Download ZIP`。这会下载开源源码，适合开发者修改；普通用户使用上面的运行包即可。

## 手机同步

电脑和手机连接同一个 Wi‑Fi：

1. 电脑打开工作台，点击“连接设备”。
2. 选择“这台已有内容”，生成二维码。
3. 手机扫码后直接进入电脑上的工作台。
4. 如果微信里不能添加到桌面，复制手机地址栏里的完整网址，必须包含 `?pair=` 及后面的 6 位配对码，到手机准备长期使用的 Safari 或 Chrome 打开。
5. 配对成功后，必须在这个同一个浏览器里点击“添加到手机桌面”。以后也从这个桌面入口进入，不要换另一个浏览器；这样名字、头像和记录才会继续使用同一份本机数据。
6. 以后在任一设备点击“刷新”，同步两台设备的记录。

配对码有效 10 分钟。复制时漏掉 `?pair=`，或超过有效期后，浏览器会被当成新设备；重新生成二维码即可。

## 可选连接 AI

工作台本身可以独立使用。需要时再安装同一个运行包里的：

- `cola-plugin/`：在 Cola 的“技能 → 渠道 → 安装本地插件”中选择这个文件夹。
- `workbench-connector/`：连接支持 MCP（模型上下文协议）的其他 AI 工具。

Cola 插件已经把运行所需的 SDK 打进成品，普通用户不需要另外安装 Node.js、npm 或 pnpm。若 Cola 提示“同名插件已安装”，先在“已安装”里卸载旧版 Summer 工作台，再重新选择 `cola-plugin` 安装。

## 数据边界

这是纯本地版本，不依赖 Cloudflare，不需要云端账号。工作记录保存在运行工作台的电脑本地文件和各设备浏览器中，只在同一 Wi‑Fi 下按配对关系同步，不会自动上传到云端，也不会与其他人的数据混在一起。工作台会在本机同步前保留上一份安全备份；如果两台设备同时修改同一条记录，会保留冲突信息，不会静默覆盖。

## 自动检查更新

工作台启动或点击“刷新”时，会在有网络时检查 GitHub 上的版本。发现新版后会显示“查看并下载”；桌面版还会自动尝试检查更新，不需要每次主动寻找新版。当前第一版桌面包暂不上 Apple、Windows 系统签名：如果系统不允许后台替换，工作台会保留数据并提示下载新版，这是未签名环境的正常兜底。记录、头像和配对关系不会因为更新而要求重新设置。新版安装包会继续使用电脑上的独立数据目录，因此保留旧包即可回退；不要删除系统数据目录。

头像会同时保存在工作台同步数据和当前设备的安全缓存中。同步数据暂时为空、图片地址短暂失效或升级程序时，工作台会优先恢复已有头像，不会用默认头像静默覆盖。

## 开发者

需要 Node.js `>=22.13.0` 才能从源码重新打包：

```bash
npm install
npm run package:offline
```

源码修改和测试说明见项目目录中的 `package.json` 与 `tests/`。
